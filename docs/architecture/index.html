03 / Source of truth

Policy → skill → agent

Policies define intent. Skills define a focused analysis. Agents select relevant skills. Humans retain accountability.

Policy

WHAT must be true. Stable IDs, MUST / SHOULD / MAY language, exceptions, owners, and automation candidates.

Skill

HOW to check it. A reusable analysis contract with inputs, procedure, output, severity, confidence, and human review.

Agent

WHICH skills should run. Contextual routing and consolidated findings, always advisory.

Workflow

WHEN to run. PR context, changed paths, policies, CI results, and developer evidence.

Human

WHO decides. Risk, exceptions, production, IAM, architecture, security, data, AI, and merge accountability.

PolicyDefines WHAT must be true.
Example: SEC-001 → Secret Review Skill → Security & DevOps Agent → Pull Request → Human escalation when required.
04 / Engineering intelligence

Four custom agents

These are repository contracts for advisory domain review, not autonomous replacements for CI, GitHub, or human governance. Click a card to expand its actual skills.

ARCH-AGENT-001

Architecture Agent

Architecture, dependencies, APIs, boundaries, data contracts, ADRs.

  • Architecture review
  • Dependency analysis
  • ADR review
Read-only by default. Escalates material design and boundary decisions to architecture owners.
SEC-DEVOPS-AGENT-001

Security & DevOps Agent

Security, IAM, secrets, CI/CD, IaC, environments, deployment and rollback.

  • Secret / IAM / dependency review
  • CI / CD / IaC review
Cannot access production credentials, change IAM, suppress scanners, approve deployment, or override deterministic controls.
AI-AGENT-001

AI Engineering Agent

Models, prompts, RAG, evaluations, guardrails, cost and AI risk.

  • Model review
  • Prompt review
  • Evaluation review
Escalates consequential, unsafe, sensitive, or irreversible AI behavior to humans.
QUAL-AGENT-001

Code Quality Agent

Maintainability, tests, complexity, duplication, documentation and errors.

  • Code review
  • Test review
Does not replace formatting, linting, or deterministic tests and cannot waive their results.

06 / Enforcement boundary

Deterministic CI vs AI assistance

Contextual reasoning is valuable, but reliable rules belong in deterministic checks first.

Deterministic CI / CD

  • Repository and policy validation
  • Formatting, linting, and tests
  • Secret and dependency scanning
  • SAST, IaC, and container checks when applicable
  • Artifact digest verification
  • Environment and deployment protections

AI-assisted agents

  • Architecture reasoning
  • Trade-off analysis
  • Contextual security review
  • AI design and evaluation review
  • Code quality reasoning
  • Recommendations and explanations
Rule of thumb: if it can be reliably checked deterministically, prefer CI. Use agents where contextual reasoning adds value.

10 / Operating principles

Engineering principles

The framework favors explicit, auditable controls over platform complexity.

Secure by default

Security controls exist from repository creation.

Policy driven

Stable IDs connect intent to future enforcement.

Deterministic before AI

Reliable rules belong in CI/CD.

Human accountable

High-risk decisions require qualified people.

Least privilege

Access, identities, and agents get only what they need.

Technology neutral

Overlays add stack and platform specifics.

Reusable

Projects share the same safe starting path.

Traceable

Changes, artifacts, approvals, and deployments connect.

Fail safely

Uncertainty escalates instead of silently passing.

Simple by default

Small, reviewable controls beat unnecessary orchestration.

12 / Rationale

Why this architecture?

Each layer has a deliberately narrow responsibility.

Why policies?

To make engineering intent explicit, reviewable, and reusable.

Why CI?

To deterministically enforce rules that can be reliably automated.

Why agents and skills?

To add contextual reasoning and reusable analysis where automation alone is not enough.

Why humans?

To retain judgment and accountability for risk, exceptions, and production.
